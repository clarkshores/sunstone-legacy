## What to upload

From the repo root, upload ONLY these:

    src/                  (the whole tree — .ts, .html, .css, assets manifests)
    package.json
    tsconfig.json
    vite.config.* / rollup.config.* / whatever the bundler config is
    capacitor.config.*
    index.html            (the bundler entry, if it lives at the root)

Drag the folders in as folders; Drive preserves the tree and Claude walks it.

## Why this is a mirror, not repo access

Claude can read and write files here, but this is NOT git. Claude cannot
branch, commit, push, open a PR, or see history. The workflow is:

 1. Clark uploads src/ here.
 2. Claude reads it, ports the bundle changes into the .ts files, and
    writes the CHANGED files back here under `ported/` with a
    PORT_NOTES.md listing every file touched and why.
 3. Clark or Zero copies `ported/` over the working tree, runs the build,
    runs the test suites against the built output, and commits.

Step 3 stays human/Zero — that is where the git operations and the review
happen.

## Before uploading, one decision worth making

Porting seven rounds of bundle patches into TypeScript by hand is real work
and carries real risk of silent divergence: the bundle is verified by 35
browser tests, a hand port is not verified until it is rebuilt and retested.

The alternative is to stop treating the TS source as the source of truth and
let the canonical bundle BE the build artifact — Capacitor wraps
`sunstone-v0.14.CANONICAL.html` as `www/index.html` and ships it. The repo's
job becomes packaging, not compiling. That removes the port from the critical
path to the App Store entirely, at the cost of the TS source going stale.

Port if the TS source has long-term value. Freeze if the goal is to ship in
two weeks. Claude will do either; Zero should make the call.
